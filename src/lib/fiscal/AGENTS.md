- Fiscal regime options and certificate-validity rules live in src/lib/fiscal; A1 certificates are parsed in-browser, stored in the private certificados-digitais bucket per estabelecimento/unidade, and passwords go to unidade_certificado_senhas (write-only for clients) so they are never read back in the UI.
- Item taxation (CFOP, CST/CSOSN, ICMS/ST/DIFAL/FCP, IPI, PIS/COFINS) comes only from the external Systax engine via the systax-calcular function; motorFiscal.ts builds the request from saved company/unit/product fiscal fields and normalizes the reply. Credentials live in systax_config (write-only RPCs). There is no internal rule table (regras_fiscais is deprecated).
- Fiscal operation types (fiscal_tipos_operacao) map to a Systax operacao_base plus NF-e finalidade/estoque/cobrança; per-order consumidor final, destinação and presença are chosen at invoicing, saved on the order and nota, and resolved by consumidorFinalVenda so Systax and the emitted NF-e agree.
- Unit fiscal lookup goes through nfe-focus acao consultar_cnpj (Focus CNPJ base, company token server-side); it fills regime/CRT/CNAE and IE only when the reply carries it, never guessing.
- Transport (modFrete, carrier = empresa flagged transportadora, plate, volumes/weights), payment (condicoes_pagamento meio/parcelas/intervalo → formas_pagamento and duplicatas) and unit série/next number/ST IE per UF are chosen at invoicing or in cadastros and sent by nfe-focus, so the emitted XML matches what was saved.
